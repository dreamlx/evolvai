# ADR-007: EvolvAI 与 Serena 互补关系架构决策

## 状态

已接受

## 日期

2024-11-21

## 背景

在同步上游 Serena 项目（231 commits）后，发现上游在以下方面有显著改进：
- 两层缓存系统（two-tier-cache）
- LSP 性能优化
- 符号检索优化
- TaskExecutor 任务队列

这引发了对 EvolvAI 定位的重新思考：
1. 我们的工具是否与上游功能重叠？
2. EvolvAI 的差异化价值是什么？
3. 如何与上游保持互补而非竞争？

## 决策

### 核心决策：定位为策略层，而非执行层

**EvolvAI 定位**：AI 工具使用策略引擎

**关键区别**：
- Serena 优化**执行效率**（每次调用更快）
- EvolvAI 优化**使用策略**（调用更少、更精准）

### 架构分层

```
┌─────────────────────────────────────────────┐
│  EvolvAI (策略层)                            │
│  ┌─────────────────────────────────────┐    │
│  │ • ExecutionPlan 约束系统             │    │
│  │ • TPST 分析                         │    │
│  │ • 区域检测                          │    │
│  │ • Propose/Apply 安全模式             │    │
│  └─────────────────────────────────────┘    │
├─────────────────────────────────────────────┤
│  Serena (执行层)                             │
│  ┌─────────────────────────────────────┐    │
│  │ • LSP 符号分析                       │    │
│  │ • 缓存优化                          │    │
│  │ • TaskExecutor 任务队列              │    │
│  │ • 多语言支持                         │    │
│  └─────────────────────────────────────┘    │
└─────────────────────────────────────────────┘
```

### 差异化能力保持

| 能力 | 上游有无 | 决策 |
|------|----------|------|
| ExecutionPlan 约束系统 | ❌ | 核心保持，强化 |
| TPST 分析 | ❌ | 核心保持，强化 |
| 区域检测 | ❌ | 核心保持，强化 |
| Propose/Apply 模式 | ❌ | 保持 |
| batch_edit | 部分重叠 | 评估重构 |

### 集成关系

1. **ToolExecutionEngine 与 TaskExecutor**
   - TaskExecutor：底层任务队列管理
   - ToolExecutionEngine：高层 4 阶段执行逻辑
   - 关系：互补，不冲突

2. **工具注册机制**
   - EvolvAI 工具通过 ToolRegistry 注册
   - 与上游机制完全兼容

3. **LSP 管理**
   - 使用上游的 ls_manager.py
   - 在 tools_base.py 中调用 save_all_caches()

## 后果

### 正面

1. **清晰的定位**：策略层 vs 执行层，避免重复造轮子
2. **互补价值**：利用上游优化，专注差异化
3. **维护效率**：减少重叠代码，降低同步成本
4. **用户价值**：获得两层优化的叠加效果

### 负面

1. **依赖风险**：上游 API 变更可能影响集成
2. **同步成本**：需要定期同步上游改进
3. **复杂度**：两层架构增加理解成本

### 缓解措施

1. **定期同步**：建立上游同步流程（每月或按需）
2. **兼容性测试**：添加针对上游 API 的测试
3. **清晰文档**：说明两层关系和使用场景

## 替代方案

### 方案 A：完全独立开发（已拒绝）

优点：无上游依赖
缺点：重复造轮子，失去 LSP 能力

### 方案 B：完全合并到上游（已拒绝）

优点：无同步成本
缺点：失去差异化，决策受限

### 方案 C：策略层扩展（已采用）

优点：互补、高效、差异化
缺点：同步成本
